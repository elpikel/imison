# Decision log

Dated decision log: what, why, what was rejected.

- 2026-11-11: Claude kit set up (copied from ether). Repo is a plain Mix library, not a Phoenix app; web and DB rows in `.claude/project.md` point at the host app and the future `dev/` app.
- 2026-11-11: Design adopted from "Imison: architecture and user stories" (`docs/PROJECT.md`). Name is Imison (`:imison`), matching the repository and the `mix new` skeleton. ADRs 0001–0003 accepted; 0004 (built-in login) and 0005 (no hard Oban dependency) proposed until the open decisions are settled.
- 2026-11-11: Tooling: Styler formatter plugin, Credo `--strict` with the ExSlop plugin.
- 2026-11-11: Work tracking: no issue tracker; plans and tasks live in `.claude/work/<slug>/`; `/implement` needs a feature branch off `main`.
- 2026-11-11: Dashboard design added as static mockups in `docs/design/` (`app.css` + one HTML page per screen). LiveViews reuse its markup and class names. `app.css` moved to `priv/static/app.css`, the shipped asset, and the mockups link to it.
- 2026-11-11: Fonts bundled instead of loaded from Google Fonts, so host apps' dashboards make no third-party requests and pass strict CSP. Instrument Sans (variable, 400–700) and JetBrains Mono (400, 600), latin + latin-ext WOFF2 from Fontsource 5.3.0, in `priv/static/fonts/` with their OFL 1.1 licenses, which the OFL requires when redistributing. Rejected: system font stack (loses the design's look).
- 2026-11-11: Backlog in `docs/STORIES.md`: the design's 36 stories with IDs, build order, dependencies and "done when" lines, plus DEV-01 (test database) and DEV-02 (`dev/` host app) as setup. Replaces the story table in `PROJECT.md` so there is one list.
- 2026-11-11: `mix check` alias runs in the test env: `compile --warnings-as-errors --force`, `deps.unlock --check-unused`, `format --check-formatted` (Styler), `credo --strict` (ExSlop), `test`. It stops at the first failure.
- 2026-11-11: Test database (DEV-01): `mix test` runs the standard alias `ecto.create` + `ecto.migrate` on `imison_test`, never drops it. After editing an unreleased `Imison.Migration` version, reset by hand with `MIX_ENV=test mix ecto.drop`, then `mix test`. Rejected: dropping and recreating on every run; migrating from `test_helper.exs` with `Ecto.Migrator`. Wrapper migrations live in `test/support/postgres/migrations/` (test repo `priv:`), outside the package, one per released version, as a host app does.
- 2026-11-11: `Imison.Migration` added as a stub in DEV-01: `up/1` and `down/1` are no-ops, so the test repo's wrapper migration goes through it now and INS-02 only adds version 1. Rejected: leaving the wrapper migration empty until INS-02 (misses DEV-01's "done when").
- 2026-11-11: `ecto_sql ~> 3.14` and `postgrex ~> 0.22` added as required dependencies now: they were already planned runtime deps in `docs/PROJECT.md`, and the test repo needs them. Rejected: `optional: true` (Imison's migration and schemas always need them, as Oban's do).
- 2026-11-11: Tests cover Imison's behaviour only: no tests of framework behaviour (Ecto's SQL sandbox or migrator) or of no-op stubs. DEV-01 adds no tests of its own: `mix test` going green through the `ecto.create` + `ecto.migrate` alias is the check, and sandbox isolation, test-only compilation and the wrapper migration running were checked once by hand. Real database tests arrive with INS-02, which uses `Imison.DataCase`.
- 2026-11-11: Development host app (DEV-02): `dev/` is a gitignored, local-only Mix project with a path dependency on Imison (user's choice: not pushed to the repo), so the library's `mix.exs` and deps are unchanged and `dev/` can't enter the Hex package. Built by hand: endpoint, router, one controller with sample error routes and an error view; `mix dev` creates and migrates `imison_dev` and starts the server. Errors render as plain text (no `phoenix_html`). Checked by hand, no tests. Rejected: a `dev.exs` script with `only: :dev` deps in the library's `mix.exs` (dev-only code and deps in the repo); a committed `dev/` project; `phx.new` (assets and generators the app doesn't need).
- 2026-11-11: Config validation (INS-05) follows Oban: `Imison.start_link/1` calls `Imison.Config.new/1`, which raises `ArgumentError`, so a bad config fails the host's boot. `Imison.Validation` is hand-written, modelled on `Oban.Validation` with only the types Imison uses. Unknown options are rejected with a "did you mean" hint; duplicate options are rejected; `repo` must export `config/0`, `mailer` `deliver/2`, and `ignore` entries must be exception modules. The config is stored in `Imison.Registry` (started by `Imison.Application`) as Oban does in `Oban.Registry`, and read with `Imison.config/1`. `%Imison.Config{}` holds every documented option with its default; `channels` defaults to `[]` until NOT-01 adds the email channel. Error messages print the given value, as Oban's do. Rejected: `nimble_options` (Oban hand-writes its validator; no new dep); validating only the three options used now; redacting credential values in messages (user's choice to keep Oban's format).
- 2026-11-11: Migrations (INS-02) mirror Oban. `Imison.Migration` is the public module and a behaviour (`up/1`, `down/1`, `migrated_version/1`) that dispatches on the repo's adapter; `Ecto.Adapters.Postgres` → `Imison.Migrations.Postgres` is the only mapping. The applied version is recorded as a comment on `imison_errors`; `up()` migrates to the latest, `up(version: n)` applies only missing versions, `down(version: n)` rolls back to n−1. `V01` creates the six tables with `create_if_not_exists`. A `prefix:` option puts them in another Postgres schema (created when missing), with a matching `prefix` config option, default `"public"`. Ids are explicit `bigserial`, references `bigint` and timestamps `utc_datetime_usec`, so the host repo's migration config can't change them. Status-like values are text (schemas validate them later). Other indexes wait for the stories whose queries need them. Until the first Hex release later stories edit `V01`; afterwards each change is a new version. INS-07 is folded in: Oban's version tracking is its "done when". `.formatter.exs` imports the `ecto` and `ecto_sql` formatter config so the migration DSL has no parentheses. Rejected: Postgres logic directly in `Imison.Migration` without dispatch or prefix; `V01` without version tracking (INS-07 would rewrite it).
- 2026-11-11: Name fixed to Imison, matching the repository: the design doc's spelling with an extra "i" had been adopted earlier the same day and is replaced everywhere (OTP app `:imison`, modules `Imison.*`, tables `imison_`, env vars `IMISON_USER`/`IMISON_PASSWORD`, test DB `imison_test`); earlier entries use the current name. Nothing was released, so no upgrade path is needed. The `.gitignore` pattern `imison-*.tar` is now correct.
- 2026-11-11: Error grouping (ERR-01, with MN-01 folded in): `Imison.Errors.record/2` is the seam the capture worker and `report/3` will call; it takes the config and a map (`kind` as a string, `message`, `stacktrace`, `context`, `release`, `occurred_at`) and writes error, occurrence and hourly count in one `repo.transact`, every write with `prefix`. Increments happen in SQL, so concurrent records from several nodes sum (MN-01). Application frames are modules of the host repo's `otp_app`; rejected: an `otp_app` config option (one more setting). With no application frame the fingerprint uses the first frame, and an empty stack trace hashes the kind alone; rejected: grouping on kind alone whenever no application frame exists (lumps unrelated crashes). The latest message wins, guarded by `occurred_at`: one `ON CONFLICT` statement sets `last_seen_at` with `GREATEST` and `message` with a `CASE` on it, so reordered or concurrent capture can't move `last_seen_at` back; rejected: keeping the first message (stale wording), a plain `set` (an older occurrence would overwrite). Hash input is kind, module, function and arity joined by `"\n"`, built with `Atom.to_string`, so an Elixir upgrade (e.g. `inspect` output) can't change fingerprints. Stored frames keep module, function, arity, file and line, never argument values. Plain structs and `insert!`, no changesets: the input is internal. MN-01's concurrency test commits real rows via `Sandbox.unboxed_run` and deletes them by a unique `kind`, so other tests assert only on their own rows.
